## 1. Zawiya Studio findings
Full notes in `docs/research/zawiya-studio.md` (observed facts kept separate from inferences). ## 6. Pricing engine
`lib/pricing/config.ts` is the single source (currency ILS, `formatMoney`, `PRICING_CONFIG_VERSION`); pure engines in `lib/estimator` (+ `lib/discuss`). Bases ₪1,500–₪12,000 (config `2026-11-v2`, repriced to be affordable for any small business), additional types at 60%, line items for features/integrations/design with documented order of operations, range = total ×0.9 / ×1.15 rounded to ₪100, week range from summed days, maintenance mapped to ₪150/₪250/₪400 per month. Overlaps are never double-charged (booking type includes online booking, dashboard type includes the admin dashboard, email automation covers customer notifications). Docs: `docs/pricing-engine.md`, `docs/discuss-flow.md`. An independent verifier hand-computed 33 scenarios (all matched) and fuzzed 45,000 random inputs (range ordering, rounding, monotonicity held). Review findings fixed: shared items (CRM, multilingual, SEO, payments) now price identically whether picked in step 3 or 5; an undecided ("not sure") project prices what was chosen.

## 7. Automation ROI maths
Exactly as specified (`docs/automation-roi.md`): `hoursPerDay = timesPerDay × minutes × employees ÷ 60` (times per employee), ×22 working days, × automation %, × hourly cost; value split into direct cost reduction (default 20% assumption), productivity value and FTE-equivalent capacity; payback and 12-month ROI on both bases (n/a when not positive); implementation ₪1,500 + ₪900/task, running ₪120 + ₪40/task. The mandatory test (3 employees × 2 h × 22 days, ₪60/h, 70%) gives **132 h, 92.4 h, ₪5,544/mo, ₪66,528/yr** — asserted in unit tests and on screen in the Playwright flow (EN + AR). UI option buckets map to documented representative numbers (`lib/roi/buckets.ts`).

## 8. Leads & email
`submitLead` (`lib/leads`): strict Zod envelope, honeypot (`website`), minimum fill time, same-origin check, per-IP and per-email rate limits, idempotency + 10-minute dedupe, **server-side recompute** of every estimate/ROI/discovery (client totals ignored), then insert and email in `after()`; with Supabase unconfigured the email is sent synchronously; if nothing can persist or send the API returns a retryable **503 — never a fake success**. Routes: `/api/estimate`, `/api/automation-roi`, `/api/discuss`, `/api/contact`. Emails go to `CONTACT_TO` (fallback `ZOHO_SMTP_USER`) with the visitor as Reply-To and include answers, estimate and the free-text note. Security review fixes: too-fast submits now get an honest retryable 429 (no silent loss; clock-skew tolerant), email rate-limit key normalised, streamed 64 KB body cap, loud warning when rate limiting is unconfigured in production. The same idempotency key returns the original reference; a resubmission from the same email+source within 10 minutes (different key) is stored and emailed, flagged as a possible resubmission of the earlier lead — it never swallows new data or returns another submission's reference. The legacy chat-lead route got the same same-origin check and streamed body cap, and the unconfigured-SMTP fallback logs only the lead ref. Docs: `docs/leads.md`.
